Design rule. The backend and this interface share identical object names and IDs. Each stage returns an auditable record consumed directly by the next stage — nothing is re-derived or renamed along the way. Hard safety gates are always evaluated before final ranking, and a gate failure can never be outweighed by a high score elsewhere.

STAGE 01

Project input

Defines the discovery scope — indication, known constraints, and how much the platform should decide versus how much is fixed in advance.

DISCOVER lets the target-discovery stage propose candidates; KNOWN_TARGET fixes the target below.

  


  

    
STAGE 02

    
Evidence engine

    
Normalizes every source of expression, localization, and safety evidence into one schema before any target is scored.

    

      
FieldMeaning

      
surface_evidenceCell-surface accessibility support.

      
tumor_evidenceIndication-specific tumor prevalence and expression level.

      
normal_tissue_riskIndependent safety risk estimate, kept separate from tumor evidence.

      
evidence_confidenceMeasured-evidence fraction and overall quality.

      
evidence_classPROTEIN_CONFIRMED / RNA_SUPPORTED / DATA_INSUFFICIENT.

      
cell_type_contextMalignant, stromal, endothelial, immune, or mixed.

      
isoform_statusWhether expression or risk has been resolved to the isoform level.

STAGE 03

    
Target discovery

    
Returns a ranked universe of candidate targets. This ranking reflects target-level evidence only — it is not the final candidate ranking produced later in the pipeline.

    

  


  

    
STAGE 04

    
Target pairing & logic

    
Evaluates dual-target logic gating (AND / OR / AND-NOT) where a single target's safety margin is insufficient on its own.

    

      
FieldPurpose

      
pair_idStable identifier for the target pair.

      
targetsTarget A and Target B.

      
logicAND / OR / AND-NOT.

      
pairing_robustnessStability of the pair under candidate-pool perturbation.

      
forced_pairTrue if a target had only one admissible partner.

      
combined_normal_riskLogic-aware normal-tissue risk for the pair.

      
tumor_coexpressionObserved tumor coexpression, reported with its uncertainty.

    

  


  

    
STAGE 05

    
Target-specific binder discovery

    
CPU-first module. Retrieve target-specific binders, verify antigen identity, preserve and clean sequences, annotate VH/VL/CDRs, score developability and specificity, optionally generate conservative variants, then rank.

    

      
FieldMeaning

      
binder_id / target_idStable binder-to-target relationship.

      
originRETRIEVED / OPTIMIZED_VARIANT / CPU_GENERATED_VARIANT.

      
target_matchPASS / FAIL / UNKNOWN.

      
sequence_original / sequence_cleanUnmodified source sequence and cleaned mature sequence, when justified.

      
provenanceSource IDs, publication or structure links, transformation history.

      
developability_scoreSequence-level liability score.

      
specificity_riskHuman-homolog / off-target proxy.

      
structural_evidenceNull unless a verified binder–antigen complex exists.

      
binder_scoreFinal ranking score, computed after hard checks.

    

    
Required behavior. If no valid target-specific binder exists, the stage returns BINDER_DISCOVERY_REQUIRED. A generic adaptor or tag binder is never substituted silently.

  


  

    
STAGE 06

    
CAR architecture

    
Combines an eligible target (or pair), a ranked binder, and the safety policy into a complete construct.

    

      
InputOutput

      
Eligible target/pair + ranked binder + safety policyArchitecture, domain map, complete sequence, payload size, construct provenance.

      
Single targetSINGLE or ADAPTOR, depending on policy and evidence.

      
Target pairAND / OR / AND-NOT, if admissible.

      
No qualifying binderBINDER_DISCOVERY_REQUIRED.

    

  


  

    
STAGE 07

    
Structural evidence

    
On CPU-only infrastructure, this stage uses verified, deposited structural evidence where it exists. Where no valid binder–antigen structure exists, it returns UNKNOWN rather than an invented score.

STAGE 10

    
Hard gate filter

    
Every candidate must clear these gates before it is eligible for ranking. None can be offset by a strong score elsewhere.

    

      
GatePASS requirement

      
surface_gateTarget is accessible on the cell surface.

      
cell_type_gateNot primarily a stromal/immune signal masquerading as a tumor-cell target.

      
normal_tissue_gateRisk below the configured policy threshold for the chosen architecture.

      
evidence_gateSufficient evidence to support the decision, or explicit routing to REQUIRES_EVIDENCE.

      
binder_gateVerified, target-specific binder sequence available.

      
construct_gateComplete construct generated.

      
packaging_gatePayload fits the delivery budget.

    

  


  

    
STAGE 11

    
Final candidate ranking

    
The user-facing decision layer. Only gate-passing candidates are ranked, and each keeps both a scalar score and its Pareto-front status.

    

    
Eligible candidate score =
  Σ (weight_i × normalized_component_i) × evidence_confidence_adjustment

Rules
  · a hard-gate failure cannot be rescued by a high score
  · unknown components are recorded as null, never as zero
  · weights are versioned and configurable
  · measured_fraction is reported alongside the score
  · Pareto-front membership is retained, not collapsed into the scalar

Engineering rules

      
    
        
  • Unknown evidence is represented as null or UNKNOWN — never estimated silently.
    • 
        
  • Every object carries a stable ID and its provenance.
    • 
        
  • Every score is tagged with the model/weights version that produced it.
    • 
        
  • API errors name the specific field that failed validation.
    • 
        
  • Long-running jobs are asynchronous, polled via run_id.
    • 
        
  • Run state persists outside process memory.
